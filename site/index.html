Every verdict comes with the rows that prove it.

WhyTrace investigates a flagged university account across sign-ins, MFA, VPN, mail and the CISA known-exploited list, then decides: contain, monitor, benign or escalate to a human. A Critic re-runs its own queries before any claim survives.

Below is a replay of a recorded live run — real Zetaris queries, real Nemotron receipts. Nothing on this page calls a model.

Six tables, read in place.

    
Identity, sign-ins, VPN sessions, mail events, devices and CISA KEV live in different systems. Zetaris joins them as one semantic layer with data-quality rules. Nothing is copied into WhyTrace; every fact an agent uses is a query with an id.

  

  

  

    
How one investigation runs

    
    
    
    
  
    

    


    
  
    
    
    Six checks between a model and a verdict.
    
    
    A language model is good at proposing explanations and bad at knowing when it is wrong. WhyTrace lets Nemotron propose, then makes every claim survive checks that do not trust it.
    
  
    
  
    
    
    01
    Evidence contract
    Every finding carries a sql_id (SHA-256 of the query text) and the row references Zetaris returned. A finding without rows cannot reach the report.
    sql_id + rows
    
    
    02
    Independent Critic
    The Critic writes its own, different query to re-check each claim. Near-miss IPs, shifted times, wrong counts and invented CVEs are struck out.
    126/126 planted claims caught
    
    
    03
    Scout quarantine
    Mail subjects, rule names and user agents are attacker-controlled. Scout Intent finds instructions hidden there and passes them to the model as data, never as commands.
    injection precision 1.00 · recall 1.00
    
    
    04
    Deterministic Risk Gate
    A fixed policy over confirmed findings decides; the model's opinion is checked against it. When they disagree without grounded evidence, a human gets the case.
    0 false contains on blind sets
    
    
    05
    Report validator
    validateReport() rejects any sentence that does not cite a finding, and any unsupported causal story.
    21/21 causal plants rejected
    
    
    06
    False-premise traps
    Three alerts that loudly claim a takeover the data does not show. The agent has to disagree with the alert, from the rows.
    3/3 refused · 0 lock-outs
    
  
    

    


    
  
    
    
    How much each piece of evidence mattered.
    
    
    The verdict comes from a deterministic policy, so we can measure it exactly. Shapley values split the decision among the findings; switch a finding off to see whether the verdict would change.

    Measured against the two obvious alternatives.
    
    
    Same cases, three systems: a rules engine like the ones SIEMs ship, Nemotron on its own with the raw events, and WhyTrace. Then we did the uncomfortable part — cases written by someone who never saw our code.
    
  
    
  
    
  
    
  
    
  
    

    


    
  
    
    
    Confident when right. Less sure when wrong.
    
    
    Accuracy is not the whole story for a tool that can lock someone out. The Brier score punishes confident wrong answers; lower is better. WhyTrace scores lowest on all three test sets, including both blind ones.
    
  
    
  
    
    
    
    
    
      
    Every miss is published
    
      
    On the blind sets, rules were more accurate. They were also the system that locked out innocent users. WhyTrace locked out no one on either blind set. On set A, v1 still cleared three attacks as benign; after the v2 fixes, every miss on set B went the cautious way: escalate to a human.
    
      
    Each miss has a cause read from its trace and a general fix candidate — no case names in the code.

    What the blind test taught us.
    
  
      
    
    1. Dev set: 19 of 21. Seven cases we wrote ourselves, three independent runs each. It looked great — and that was the problem.
      2. 
    
    2. Blind set A: 12 of 24. Eight cases written by an analyst who never saw the code. Rules scored 15. WhyTrace locked out no innocent user; rules locked out three and missed six attacks.
      3. 
    
    3. We published it and wrote down why. Each miss has a cause from its trace and a general fix candidate — no case names in code.
      4. 
    
    4. Blind set B, v2: 15 of 24. New unseen cases, frozen code, one run. Rules scored 18 and Nemotron alone 17 — but rules locked out innocent users six times. WhyTrace locked out none and cleared no attack as benign; every miss was a cautious hand-off to a human.
